# 已选方向：灰白简洁的进销存

日期：2026-11-08。用户授权按系统用途选择后，选 C 为主方向；A、B 继续作为候选保存。
这是设计约定，不是宣称三端模板或原业务系统已经全部换好界面。

## 为什么选 C

- 用户要白色、实用、不花哨；C 的白底、灰色控件、浅分隔线比较贴合。
- 采购、库存和对账需要比较单号、材料、数量与金额，不需要大横幅或装饰性数据卡片。
- 现有系统已使用绿色主要操作及红色库存预警，可以保留，不必为了参考图重做所有颜色。

## 通用视觉

- 白色为主体，中性灰用于辅助文字、输入区和细线，不使用蓝色大通栏、渐变或装饰光效。
- 深色正文、明确的文字层级，数量和金额对齐；字体使用系统中文字体，不新增外链字体依赖。
- 小圆角、轻边框；页面分区不层层包成卡片，不加大阴影或无用动画。
- 绿色用于主要操作及选择态；红色用于库存不足、输入错误和危险操作，不用颜色代替状态文字。
- 手机按钮须适合触控，长单号、供应商名、型号须换行或合理截断，不与状态重叠。

## 电脑网页

保留紧凑表格、常用筛选、固定顺序的字段及金额汇总。操作靠近对应单据，次要信息不抢主要数字。
不复制原参考项目的侧栏菜单、复杂会计或制造模块。

## 微信小程序与手机 H5

以纵向单据和分组表单为主，不缩小桌面表格。

采购列表优先显示单号与状态，再显示供应商、采购人、日期；详情继续显示材料、数量、收货批次与审核记录。
库存优先显示材料、型号、单位、剩余量和预警；对账明确供应商、月份、实收与未交部分。

手机布局借鉴已研究的普通单据分组，不采用商城促销、彩色 emoji 功能墙或完整 ERP 工作台。
所列布局仍需在具体页面和真实数据下逐页实现、截图及验证。

## 业务不变

分批实际收货、老板审核、领料库存、低库存预警、按实收月份对账及既有权限边界保持原约定。
视觉选择不新增零售、会员、复杂多仓，也不把员工备货完成改成自动发货。
